# ปิดข้อมูลส่วนบุคคลก่อนส่ง AI ทุกครั้งด้วยป้ายที่เติมค่ากลับได้

ผู้ใช้ตอบ grill รอบแรก (Q1–Q5) รอบสอง (Q6–Q8) และรอบสาม (Q4) วันที่ 22 พฤศจิกายน 2569 ก่อนหน้านี้แชตและการวิเคราะห์ alert ส่งข้อมูลให้ผู้ให้บริการ AI โดยไม่ปิด เช่น ชื่อคนขับ ทะเบียนรถ ชื่อผู้ขอ และสำหรับแอดมินยังมีชื่อเต็ม อีเมลงาน และรหัสพนักงาน ต่อไปนี้ทุกข้อความที่ server ส่งให้ผู้ให้บริการ AI ทุกรายในทุก environment ต้องผ่านจุดปิดข้อมูลจุดเดียว และไม่มีสวิตช์ปิด จุดนี้แทนข้อมูลส่วนบุคคลและรหัสลับด้วยป้ายที่นับใหม่ทุกรอบ AI แล้วเติมค่าจริงกลับสองที่ คือใน argument ของเครื่องมือก่อนค้นฐานข้อมูล และในคำตอบก่อนแสดงผู้ใช้ แนวทางนี้ตาม ADR 0014 ของโปรเจกต์ DED Center

- **ขอบเขต (รอบแรก Q1):** ปิดเฉพาะข้อมูลส่วนบุคคลและรหัสลับ ไม่ปิดข้อมูลธุรกิจและข้อมูลงาน เพราะ agent ต้องใช้คิดเลขและเทียบยอด และใช้เลข PO เป็นกุญแจค้น
- **วิธีหา (รอบแรก Q4):** ใช้สี่ชั้น
  1. คอลัมน์ที่ทำเครื่องหมายไว้ใน catalog และในหลักฐานของ alert
  2. รูปแบบในข้อความอิสระ ได้แก่ เบอร์โทร อีเมล เลขบัตรประชาชน (ตรวจหลักสุดท้าย) ทะเบียนรถ ลิงก์ LINE ID ชื่อหลังคำนำหน้า และรหัสลับ
  3. ชื่อที่ระบบรู้จัก
  4. คำที่ต้องปิดเสมอ

  ไม่ปิดตัวเลขยาวทุกตัว เพราะตัวเลขยาวใน Synapse ส่วนใหญ่คือรหัสพัสดุ เลข PO และเลขแผน
- **ส่งเท่าที่ต้องใช้ (รอบแรก Q5):** ทะเบียนคน ได้แก่ คำขอสิทธิ์ โปรไฟล์ผู้ใช้ และบันทึกการแก้ไข ไม่เป็นแหล่งข้อมูลของแชต และไม่ส่งคอลัมน์ user id ให้โมเดล
- **ตารางจับคู่ป้าย:** อยู่ในหน่วยความจำของรอบนั้นเท่านั้น ไม่บันทึกและไม่ส่งออก
- **ป้ายที่ผิด (รอบสอง Q6):** ป้ายที่เพี้ยนแค่รูปแบบ เช่น `[ชื่อ - 1]` ยังเติมค่ากลับได้ แต่ถ้าคำตอบมีป้ายที่ไม่มีในรอบนั้น คำตอบนั้นใช้ไม่ได้ แชตจะตอบจากหลักฐานแทน ส่วน alert จะตีร่างกลับ หลังเติมค่าจริงกลับแล้วยังมีการตรวจขาออกอีกชั้น
- **ที่เก็บ (รอบสอง Q7):** ค่าจริงเก็บเฉพาะในบทวิเคราะห์ alert ที่แสดงผู้ใช้ ส่วน log ร่างที่ถูกตีกลับ ข้อมูลวินิจฉัย และรายงานผลประเมิน เก็บเฉพาะข้อความที่เป็นป้าย จำนวนค่าที่ถูกปิดเก็บแยกตามวัน งาน และชนิด โดยไม่มีค่าจริง และเก็บไว้ 1 ปี
- **ชื่อ (รอบสอง Q8):** ชื่อที่ระบบรู้จักถูกปิดแม้พิมพ์แค่ชื่อเดี่ยว ยกเว้นคำที่ไม่ใช่ชื่อ ผู้ขายที่เป็นบุคคลถูกปิดชื่อคน แต่ชื่อบริษัทไม่ถูกปิด
- **คำที่ต้องปิดเสมอ (รอบสาม Q4):** ผู้ใช้ทุกบทบาทเพิ่มคำได้ และลองปิดข้อความของตัวเองได้ ระบบบันทึกว่าใครเพิ่มคำไหน และลบได้เฉพาะแอดมิน

## Considered Options

- **HMAC:** ไม่เลือก เพราะค่าเดิมให้ผลเดิมทุกครั้ง ผู้ให้บริการจึงโยงได้ว่าหลายคำถามพูดถึงคนเดียวกัน
- **เข้ารหัสด้วย AES:** ไม่เลือก เพราะโมเดลอ่านไม่ออก ข้อความยาวขึ้น และถ้าโมเดลคัดลอกผิดก็ถอดกลับไม่ได้
- **ลบทิ้ง:** ไม่เลือก เพราะจะตอบคำถามที่ต้องอ้างถึงคนหรือรถคันนั้นไม่ได้
- **ปิดตัวเลขตั้งแต่ 6 หลักแบบ DED Center:** ไม่เลือก เพราะจะปิดรหัสพัสดุและเลข PO ที่ agent ต้องใช้
- **มีสวิตช์ปิดต่อผู้ให้บริการหรือต่อ environment:** ไม่เลือก เพราะตั้งผิดครั้งเดียวข้อมูลก็หลุด

## Consequences

- ชื่อที่พิมพ์มาโดยไม่มีคำนำหน้าและระบบไม่รู้จักยังหลุดได้ จนกว่าจะเพิ่มเป็นคำที่ต้องปิดเสมอ
- ผล replay ของ alert ก่อนวันนี้วัดตอนที่ยังไม่มีป้าย จึงต้องวัดใหม่หลังเปิดใช้
