# จัดอันดับแถวใน Postgres ด้วยการค้นแบบใกล้เคียงร่วมกับการค้นเชิงความหมาย แทนการให้ LLM จัดอันดับ

ผู้ใช้ตอบ grill รอบแรก Q6, รอบสอง Q1, รอบสาม Q1–Q3 และรอบสี่ Q1 (ใช้ Cloudflare Workers AI แผนฟรี) วันที่ 22 พฤศจิกายน 2569 เดิม `query_database` ค้นแถวด้วยข้อความที่ต้องตรงทุกตัวอักษร แล้วส่งแถวที่ได้ให้ Typhoon จัดอันดับ แต่ชื่อพัสดุ 6,193 จาก 7,596 รายการ (82%) เป็นภาษาอังกฤษแบบย่อ ผู้ใช้ที่พิมพ์ "ล่อฟ้า" จึงควรเจอ "SURGE ARRESTER" ต่อไปนี้ฐานข้อมูลจะจัดอันดับแถวเอง โดยรวมอันดับจากการค้นแบบใกล้เคียง (pg_trgm) กับการค้นเชิงความหมาย (embedding จาก BGE-M3 บน Cloudflare Workers AI ใช้โควตาฟรี และเก็บใน pgvector) จึงไม่ต้องส่งแถวให้ LLM และลดการเรียก Typhoon ได้หนึ่งครั้งต่อการค้น

- คำค้นที่ส่งไปทำ embedding ต้องผ่านการปิดข้อมูลก่อนส่ง AI ตาม ADR 0001 ส่วนชื่อพัสดุเป็นข้อมูลงาน จึงส่งไปทำ embedding ได้
- ถ้ายังไม่มีคีย์ embedding, โควตาฟรีของวันนั้นหมด หรือมีการหยุดใช้ AI ของงานค้นเชิงความหมาย ระบบใช้การค้นแบบใกล้เคียงอย่างเดียว
- **ขอบเขต (รอบสาม Q2):** ทุกบทบาทค้นได้ ฐานข้อมูลกรองผลค้นตามขอบเขตของบทบาทก่อนส่งออกจาก server ไม่ปล่อยให้ AI เลือกเอง บทบาทที่ไม่ใช่เจ้าหน้าที่เขตยังไม่ผูกกับเขต
- **รายการใกล้เคียง (รอบสาม Q3):** ช่องค้นพัสดุในหน้าคำแนะนำ (Intelligence), หน้า FIFO และหน้ายอดใช้จริงของเขต ยังกรองแบบตรงตัวเหมือนเดิม ถ้าไม่เจอจะแสดงพัสดุที่ความหมายเดียวกันไม่เกินห้ารายการ แม้ตัวอักษรไม่ตรง
- การเลือกแหล่งข้อมูลยังให้ LLM จัดอันดับเหมือนเดิม เพราะส่งไปแค่ชื่อและคำอธิบายของตาราง
- คลังเอกสารจะค้นด้วยวิธีเดียวกันเมื่อมีเอกสารจริง

## Considered Options

- **PyThaiNLP (ที่ผู้ใช้เรียกว่า ThaiNLP):** ไม่เลือก เพราะใช้ได้กับภาษาไทยอย่างเดียว จับคู่คำไทยกับชื่อพัสดุภาษาอังกฤษไม่ได้ ไม่มีการค้นเชิงความหมายในตัว และต้องตั้ง server Python เพิ่ม
- **ตัวตัดคำไทยของ Node (ICU):** ไม่เลือก เพราะตัดคำเทคนิคผิด เช่น "ล่อฟ้า" ได้เป็น "ล่อ | ฟ้า"
- **BGE-M3 ผ่าน OpenRouter:** ไม่เลือก ผู้ใช้ต้องการแบบฟรี ส่วน OpenRouter ต้องเติมเครดิตขั้นต่ำราว 200 บาท และเครดิตอาจหมดอายุใน 1 ปี
- **Gemini embedding แผนฟรี:** ไม่เลือก เพราะ Google นำข้อความในแผนฟรีไปปรับปรุงบริการได้
- **รันโมเดล embedding เองบน Vercel:** ไม่เลือก เพราะโมเดลและ runtime มีขนาดใหญ่ และ function เปิดเครื่องช้า
- **ตารางคำพ้องที่แอดมินดูแล:** ไม่เลือก เพราะต้องเพิ่มคำเองตลอด
- **ParadeDB pg_search:** ไม่มีให้ใช้บน Supabase
- **embedding ของ Typhoon:** Typhoon ไม่มี API ทำ embedding

## Consequences

- Cloudflare เห็นชื่อพัสดุและคำค้นที่ปิดข้อมูลแล้ว ตามเอกสารของ Cloudflare ระบบไม่เก็บข้อมูลไว้และไม่นำไปเทรนโมเดล
- โควตาฟรีวันละ 10,000 Neurons คิดเป็นราว 9 ล้าน token ถ้าใช้เกินโควตา หรือ Cloudflare ย้าย BGE-M3 ไปแผนเสียเงิน การค้นเชิงความหมายจะใช้ไม่ได้จนกว่าจะแก้ ระหว่างนั้นระบบใช้การค้นแบบใกล้เคียงแทน
- ทุกครั้งที่นำเข้าข้อมูล ต้องทำ embedding ให้ชื่อพัสดุที่เพิ่มหรือเปลี่ยน
